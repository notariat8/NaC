## Goal and boundary

The existing [Stage A contract](../../../../workflows/verification-contracts/m365-bff-403-direct-server-diagnosis.verification.json) and its production `BLOCKED_NO_REFRESH_CAPABILITY` stop remain unchanged. A separate forward-versioned operator contract represents the specification's closed read sequence. Repository artifacts contain only fixed templates, synthetic test values, and `UNBOUND` placeholders, never real account, tenant, principal, or telemetry data. The local state can verify requirements and stops only; it performs no GET.

## Plan → Review → Fix

1. **Contract surface (AC-756-OR-01/-02/-04/-05):** Add a new `m365-bff-403-operator-read.verification.json` verification contract with DE/EN spec/plan links, five ordered resource steps (Function, narrow resource-group list GET, exactly one Insights component, optional workspace, one aggregate log query) and one closed output schema per step. Protected proof bindings start as `UNBOUND` for the exact target, account/principal, read right, BFF-to-Insights link, capture, retention, and response projection proven **before the component GET**. A similar name or Function metadata proves neither linkage nor package identity. Every later GET would have to recheck target, approval, permission, URI/query hash and proof immediately before use and atomically consume its own one-shot budget. All production budgets are zero; `provider_read_authorized`, `credential_access_authorized`, `token_refresh_authorized`, `login_authorized`, and deployment remain `false`. The contract does not revise or enable the v1 Stage A contract.
2. **Test-first (AC-756-OR-01 through -05):** Before the compiler, write synthetic positive and negative tests with fixed stop codes for subscription/component/workspace paths, URI encoding, multiple matches, `nextLink`, wrong resources, 401/403/404, retention, sampling, forbidden response fields, absent link proof, and additional requests. A 404 can mean absence only with independently proven exact scope and read rights. Reject forbidden response fields before any visible or persistent projection. A local post-response filter is **not** proof of the pre-GET projection required by the specification for the Insights component; without a technically proven transport boundary, that step remains blocked. A concurrent 403 yields at most `TEMPORAL_STATUS_ONLY`; without unique correlation, request cause and permission reason remain `UNPROVEN`. The production path must continue blocking before credential or network factories.
3. **Offline compiler and validator (AC-756-OR-02/-03):** An internal pure Python compiler satisfies the tests written first, validates synthetic bindings, and builds only deterministic URI/query representations and their hashes, with no credential or network imports. A validator checks the committed contract against fixed hosts, paths, order, API versions, KQL, field/result allowlists, and zero budgets. No free URL, query, or resource-search parameter or real evidence file becomes a CLI argument.
4. **Operator interface:** This phase adds an internal inactive verification contract and synthetic offline test module only, not a production NaC feature. A later operator surface requires a separate `nac` CLI contract with protected input/output boundaries; direct scripts are not documented as product interaction.
